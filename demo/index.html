03 // The 6 Foundational Constructs of ORDYN

Why ORDYN eliminates ambient authority at the language level
1. `entity` STATEFUL ACTOR
Autonomous, state-isolated domain component. Fields are private by default; methods must declare side-effects.
entity BankVault {
  let vault_id: String;
  mut balance: Int;
}
2. `capability` UNFORGEABLE TOKEN
Zero ambient permissions. A function cannot read disk or call network without an explicit unforgeable handle.
capability MasterKey {
  key_hash: String;
  level: Int;
}
3. `contract` FORMAL INVARIANT
First-class preconditions (`requires`) and postconditions (`ensures`). Math errors & overflow are mathematically trapped.
pub fn withdraw(n: Int)
  requires n > 0 && n <= self.balance
  ensures self.balance == old - n
4. `boundary` ISOLATED QUOTA
Hardware-isolated execution sandbox with strict memory and fuel quotas. Prevents CPU and RAM exhaustion.
boundary DefensePerimeter {
  quota { memory_limit: 32; fuel_limit: 100000; }
  bind BankVault;
}
5. `interface` TYPED PROTOCOL
Formally typed protocol specifying permissible cross-boundary calls and declared algebraic side-effects.
interface VaultOps {
  fn drain(amt: Int) -> Result
    with [AuditLog];
}
6. `flow` DATA PIPELINE
Declarative, verifiable data pipeline with compile-time information-flow tracking (`Public`, `Restricted`).
flow AuditFlow {
  source: BankVault.events;
  sink: AuditLog.syslog;
}
